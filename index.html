The feeds carry no timestamp — that is what lets published bytes be compared byte-for-byte to detect drift — so status.json is the only file with a clock, and the only way to tell a current feed from a frozen one. A source that fails keeps serving its last good feed and is marked stale here, because a blank departmental listing is worse than one a few hours old, and an unannounced stale one is worse than both.

Using a feed

Every path below is a JSON array of event objects, served over HTTPS with no authentication and no rate limit. Fetch the one you need directly.

Per-source feeds never de-duplicate

Each is a faithful representation of one upstream calendar. If you read two of them and they collide — two units listing the same talk — resolving that is yours to do, because only you know which unit's wording you want to show.

Combined feeds de-duplicate only when every detail matches

When they do, the records collapse into one whose sources array names every feed that carried it. When the start time and title match but something else differs, both records are kept and the divergence is counted — merging would mean picking a winner, and picking a winner means guessing. sources is always an array, length 1 in a per-source feed, so both kinds parse identically.

Events carry the purposes they may serve

Each record carries purposes, naming what its feed's events may be put toward. It is optional: a feed that declares none publishes none, and an event may override its feed's default. On a merged record it is the union, so an event two units both list stays eligible for everything either of them serves.

Identity is source-scoped

guid is the upstream UID, published verbatim, but those are per-site sequences rather than global identifiers: the same value names unrelated events on different sites. Key on id, which is "{source}:{guid}".
